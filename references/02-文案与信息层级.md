# 文案与信息层级

判定标准只有一条：**界面上每一句话，要么能改变用户的操作或判断，要么就不该存在。**

写界面文案时逐句过这一条。过不了的删掉，或移到字段帮助 / 帮助中心。不要用「写都写了」的心态保留。

---

## 1. 禁止的四类说明性信息

### 1.1 系统实现方式

不解释后台怎么做、数据从哪来、用什么机制。

- 禁止：`本页数据由订单服务每 5 分钟同步一次。`
- 禁止：`采用分页加载方式提升性能。`
- 禁止：`该功能基于规则引擎实现。`

### 1.2 已由控件约束的事实复述

控件已经表达了的事实，不要再写一遍。用户看得到只读状态、看得到禁用态。

- 禁止：`该字段为只读，不支持修改。`
- 禁止：`日期格式为 YYYY-MM-DD。`（日期选择器自己会显示）
- 禁止：`请从下拉列表中选择。`（它就是个下拉框）
- 禁止：`此处不可输入特殊字符。`（输入时校验并提示即可）

### 1.3 设计理由与背景解释

不解释为什么这样设计、为谁的方便考虑。

- 禁止：`为便于快速识别，此处将常用筛选项前置。`
- 禁止：`考虑到移动端体验，该区域在窄屏下折叠。`

### 1.4 帮助文档式长段落

主任务流页面不放说明书。灰底备注框、逐条解释功能的小字、折叠的「功能说明」全都不要。

- 禁止：`功能说明：本模块支持按名称、编号、状态、时间多条件组合查询，查询结果支持批量导出与批量审核……`
- 正确做法：动作用按钮表达，规则进字段帮助，完整说明进帮助中心。

## 2. 允许的七类提醒性信息

提醒性信息不是「说明」，是用户当下必须知道、会改变其行为的风险与条件。

| 类型 | 判据 | 正例 |
| --- | --- | --- |
| 操作后果 | 做完之后会发生什么 | `提交后进入甲方签署流程，签署完成前不可撤回。` |
| 不可逆 | 做了就回不去 | `作废后当前签署流程终止，已签文件不可恢复。` |
| 前置条件 | 必须先完成什么 | `需先完成甲方主体认证，才能发起签署。` |
| 时效状态 | 有时间窗或会过期 | `当前协议将在 24 小时后过期。` |
| 异常冲突 | 数据或状态有矛盾 | `当前协议与历史版本存在条款差异，请先核对再提交。` |
| 权限范围 | 用户能做什么、不能做什么 | `你当前仅有查看权限，提交需联系管理员授权。` |
| 合规安全 | 法律、隐私、安全要求 | `请勿在附件中上传未脱敏的个人信息。` |

### 2.1 写法结构

`当前状态 / 触发条件` + `后果或风险` + `建议动作`

- 差：`注意版本差异。`
- 好：`当前协议包含与历史版本不一致的条款。提交后将进入甲方签署，请先核对差异再提交。`

三要素缺一不可：只写后果不写动作，用户不知道该干什么；只写动作不写后果，用户不知道为什么要做。

## 3. 行动影响测试

对页面上每一条说明文案问三问：

1. 用户看到它之后，会不会改变操作、确认、选择或风险判断？
2. 它是否提供了控件状态无法直接表达的信息？
3. 它是否与当前任务节点直接相关？

三问全否 → 删除或移入帮助文档。有一问为是 → 继续判断提醒级别（见第 4 节）。

常见误判：把「解释得挺清楚」误当成「有用」。清楚不等于有用，有用是指能改变行为。

---

## 4. 提醒分级与展示要求

| 级别 | 什么时候用 | 展示位置 | 外观 | 可关闭 |
| --- | --- | --- | --- | --- |
| 阻断性 | 必须处理才能继续（缺失、冲突、错误） | 紧邻操作点，或替代主按钮 | 页内警告条 + 操作点红字，主按钮禁用 | 不可关闭 |
| 强提醒 | 不可逆、涉及资金、合规、签署后果 | 操作前弹窗，或操作按钮上方 | `--color-warning` 边框 + 图标 + 正文 | 不可默认关闭 |
| 一般提示 | 辅助理解但不阻断 | 区块内条带、字段下方 | `--color-primary-soft` 底 + 次要文字 | 可关闭，可折叠 |

规则：

- 同一条信息不得在页面多处重复。出现在弹窗里，就不要在页面上再写一遍。
- 提醒靠近触发点。全局顶部横幅只用于全站级影响，不要用它代替字段级提醒。
- 提醒不能替代正文、法律文本或关键业务数据。要用「查看详情」链接到原文，不要把原文塞进提醒。
- 阻断性提醒必须同时说明「怎么解决」，只报错不给路等于死胡同。

## 5. 字段帮助与提醒的区分

这两者最容易混。混了之后页面就会充满灰底说明框。

| 维度 | 提醒性信息 | 字段帮助 |
| --- | --- | --- |
| 触发方式 | 常驻或状态触发，主动显示 | 悬停/聚焦问号图标才显示 |
| 内容 | 后果、风险、条件、时效 | 定义、格式、取值规则 |
| 样式 | 警告色边、图标、条带 | 中性气泡、无强调色 |
| 位置 | 操作点上方或紧邻 | 字段标签右侧 |
| 是否影响操作 | 影响 | 通常不影响 |

字段帮助不得遮挡主流程，不得使用与提醒相同的警告样式。若一条信息既能当帮助又影响决策，按提醒处理并放在操作点。

## 6. 改法对照表

| 违规原文 | 处理 | 改后 |
| --- | --- | --- |
| `协议号由系统按上传日期 + 三位流水号自动生成，不可修改。` | 删 | 无（只读状态自己会说话） |
| `支持按名称、编号、状态组合筛选。` | 删 | 无（控件自己会说话） |
| `本页数据来源于供应商主数据系统。` | 删 | 无 |
| `修改后将同步至所有关联单据。` | 视为后果提醒 | `修改后同步至 3 张关联单据，历史版本不可恢复。` |
| `为提升加载速度，列表默认展示 20 条。` | 删 | 无 |
| `您的账号无此操作权限。` | 改写为权限提醒 | `你当前仅有查看权限。提交需联系管理员开通审核角色。` |
| `注意：合同即将到期。` | 改写为时效提醒 | `合同将于 2026-12-01 到期。到期后签署入口关闭。` |
| `请谨慎操作。` | 删或补充具体后果 | `作废后流程终止，已上传附件不可恢复。` |
| `点击此处下载模板。` | 删描述，按钮自明 | 按钮文案改为 `下载模板` |
| `暂无可导出数据，请检查筛选条件后重试。` | 保留（阻断性） | 同上，并给 `重置筛选` 按钮 |
| `功能说明：……（一段长文）` | 移入帮助中心 | 帮助入口链接 |
| `该字段最大长度 50 个字符。` | 移入字段帮助 | 问号气泡内 |

## 7. 按钮与操作文案

- 动词开头，说清动作对象：`提交审核`、`批量导出`、`作废协议`。不写 `确定`、`提交` 这类空动作（除非上下文唯一）。
- 一个按钮只做一件事。`保存并提交并通知` 拆成主次两步。
- 禁止 `点击此处`、`这里`、`点我`。
- 危险动作必须在按钮文案里就体现后果：用 `作废并终止流程`，不用 `确认`。
- 危险按钮用 `--color-danger`，次要动作用描边按钮，不要两个同权重按钮并排。
- 禁用按钮必须让用户知道为什么禁用（就近给原因，不是 title 提示）。

## 8. 状态文案结构

| 状态 | 结构 | 示例 |
| --- | --- | --- |
| 空状态（首次） | 这里会出现什么 + 主操作 | `还没有待审核商品` + `从供应商同步` 按钮 |
| 空状态（筛选无果） | 说明是筛选导致 + 重置动作 | `当前筛选条件下没有结果` + `重置筛选` |
| 加载中 | 用骨架，不写文案 | 无 |
| 错误 | 发生了什么 + 可以怎么办 | `加载失败，网络超时` + `重试` |
| 无权限 | 缺什么权限 + 找谁 | `暂无审批权限，请联系管理员开通` |
| 成功 | 做成了什么 + 下一步（可选） | `已提交，等待甲方签署` |
| 部分成功 | 成功几条、失败几条 + 查看失败项 | `12 条已导入，3 条失败` + `查看失败明细` |

## 9. 数字、单位与格式

- 数字用阿拉伯数字，千分位分隔：`12,480`。金额带币种：`¥1,280.00`。
- 单位紧跟数字并留一个空格：`24 小时`、`3.5 GB`。
- 日期用 `2026-11-26`，时刻用 `2026-11-26 14:30`，相对时间只在 24 小时内使用（`3 分钟前`）。
- 百分比保留一位小数并明确基数：`转化率 12.4%`。
- 同一页面内同类数值格式必须一致，不要一半 `1.2万` 一半 `12,480`。

---

## 10. 禁用词表

界面文案里不出现：

`注：`、`说明：`、`温馨提示`、`友情提示`、`请注意`（后接功能说明时）、`点击此处`、`这里`、`如上所述`、`详见下文`、`系统自动生成`、`不可修改`、`只读字段`、`请勿输入`、`后台`、`接口`、`规则引擎`、`同步机制`、`为了您的方便`。

技术词只在面向开发者的界面出现。面向业务用户的界面不出现 `接口`、`字段`、`参数`、`缓存`。

## 11. 自检

- [ ] 页面上没有一句「系统怎么实现的」
- [ ] 没有复述控件自身状态的话（只读、必填、格式）
- [ ] 没有解释设计理由的句子
- [ ] 没有灰底备注框、没有「功能说明」段落
- [ ] 每条保留的提醒都过了行动影响测试
- [ ] 每条提醒都写清了「后果 + 建议动作」
- [ ] 同一条信息没有在多处重复
- [ ] 字段帮助与提醒样式不同、位置不同
- [ ] 空状态、错误态、无权限都给了下一步动作
- [ ] 没有禁用词表里的词
