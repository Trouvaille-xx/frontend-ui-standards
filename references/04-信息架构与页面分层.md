# 信息架构与页面分层

这份文件的用途：决定信息放哪一层、页面怎么拆、什么时候用 Tab 什么时候用弹窗。写页面前读一遍，评审时用它当裁判。

---

## 1. 先定层级的原因

层级定错，视觉怎么调都救不回来：

- 所有信息挤在一层 → 用户要在同一屏里做取舍，决策成本按区块数量线性上升。
- 主任务和辅助任务同权重 → 用户第一眼找不到该点的按钮，只能全页面扫。
- 后续要加功能 → 只能在已有页面上继续加卡片，越加越像后台模板。

层级定对的收益是复利的：新增功能有明确的落点，页面不会越长越胖，评审也有可判定的标准。

---

## 2. 层级阶梯（由外到内，逐级判断）

| 层级 | 承载什么 | 不承载什么 | 典型形态 |
| --- | --- | --- | --- |
| 全局导航 | 业务域、一级模块 | 具体对象、操作 | 顶部栏、侧边栏、底部 Tab |
| 页面 | 一个主任务 | 第二个主任务 | 路由页 |
| Tab / 步骤 | 同一对象的不同信息组、线性流程 | 完全不同对象 | 分段控件、步骤条 |
| 区块 | 页面内的一段结构 | 独立完整任务 | 卡片、表格、表单分组 |
| 抽屉 / 弹窗 | 轻量详情、确认、短表单 | 长流程、多步编辑 | 右侧抽屉、居中弹窗 |
| 行内提示 | 与当前操作点直接相关的提醒 | 通用说明 | 字段下方提示、行内警告条 |
| 字段帮助 | 一次性查阅的说明 | 需要用户当下决策的信息 | 问号气泡、帮助中心链接 |

判断口诀：**从外往里走，能不能在上面一层就完成；能，就不要进来。**

---

## 3. 单页职责单一

### 3.1 主任务的定义

一个页面只让用户干成一件事。主任务用一句话写出来，动词开头：

- 对：`从待审核列表里选中一条并完成审核`
- 错：`管理供应商商品`（这是模块名，不是主任务）

### 3.2 主任务测试

三问，任一答不上来就说明页面职责不单一：

1. 这个页面唯一的主按钮/主操作是什么？只有一个答案才算通过。
2. 用户离开这个页面时，应该完成哪一件事？
3. 把页面上的次要区块全删掉，主任务是否仍然完整？

### 3.3 允许且鼓励多层进入

复杂对象 → 详情页；轻量详情 → 抽屉；线性流程 → 步骤条；并列信息组 → Tab；高风险确认 → 弹窗。

不要为了「少点一次」把所有内容平铺在一页。少一次点击换来的是每次都要多扫十行。

## 4. 信息分派决策表

| 信息类型 | 放哪一层 | 理由 |
| --- | --- | --- |
| 对象列表与筛选 | 一级页面 | 决策信息，高频 |
| 单条对象详情 | 详情页或右侧抽屉 | 低频、需上下文时用抽屉 |
| 编辑表单（3 字段以内） | 弹窗 | 不离开上下文 |
| 编辑表单（4 字段以上或含子表） | 独立页面 | 弹窗装不下，且需要校验反馈空间 |
| 批量操作 | 列表页工具栏 + 二次确认 | 危险动作要确认 |
| 统计与趋势 | 独立看板或页内一段图表 | 不与操作混排，避免一页面板 |
| 操作历史 / 审计日志 | 详情页内的 Tab 或独立页 | 低频查阅 |
| 功能说明文档 | 帮助中心或侧边帮助 | 不进主任务流 |
| 字段填写规则 | 字段帮助 | 只在聚焦该字段时可查 |
| 高风险确认 | 弹窗 | 逼一次明确选择 |
| 线性流程（3 步以上） | 步骤条 + 独立页 | 允许回退查看上一步 |
| 并列信息组（2–6 组） | Tab | 同一对象，避免纵向堆叠 |
| 次级动作（导出、复制、归档） | 更多菜单 | 主按钮只留一个 |
| 空状态引导 | 页面内或区块内 | 就近给下一步动作 |
| 权限不足提示 | 操作点就近 | 说明不能做，并给下一步 |

## 5. 组件选型决策表

### Tab

- 用在：同一对象的并列信息组，2–6 个，切换后不需要保留滚动位置。
- 不用在：完全不同对象之间（那是导航，不是 Tab）；超过 6 个（改用菜单或独立页）。
- 约束：Tab 标签用名词，不用动词；切换不刷新页面；首个 Tab 默认选中；URL 可寻址更佳。

### 抽屉

- 用在：轻量详情、上下文内查看与编辑，用户需要保留背后的列表。
- 不用在：需要长时间停留的复杂编辑；移动端窄屏（宽度不够，改全屏页）。
- 约束：宽度 320–480px；从右滑入 320ms；Esc 关闭；打开时焦点移入，关闭后焦点归还触发元素。

### 弹窗

- 用在：高风险确认、3 字段以内的短表单、需要打断的中断式决策。
- 不用在：长表单、嵌表格、多步流程；不要弹窗上再弹窗。
- 约束：正文写清后果与不可逆性；主次按钮明确（危险动作用危险色，不做同权重双按钮）；Esc 与点遮罩可关闭（破坏性确认除外）；焦点陷阱必须有。

### 多级页面

- 用在：复杂对象（列表 → 详情 → 子对象）；需要分享链接的视图。
- 约束：层级不超过 3 级；每级都有面包屑或明确返回；返回后保留上一级的筛选与滚动位置。

### 菜单

- 用在：次级动作收纳、右键上下文菜单、超过 4 个同级动作。
- 不用在：主操作（主操作必须在页面上可见）。
- 约束：菜单项用动词短语；危险项放最后并用危险色；支持 Esc 关闭与方向键导航。

### 步骤条

- 用在：线性、不可跳步、有校验的流程。
- 不用在：可任意顺序的并行填写。
- 约束：允许回看已完成步骤；当前步高亮；步骤名用名词短语；超过 5 步拆分流程。

### 折叠面板

- 用在：同一层级内的可选高级设置、FAQ。
- 不用在：用户必须看到的核心信息（默认收起等于藏起来）。
- 约束：chevron 旋转 180° 表示状态，200ms；状态不因刷新丢失。

## 6. 一页面板式的识别信号

命中 2 条以上就要重构：

- 一屏内同级区块 ≥ 4 个
- 主任务与辅助任务视觉权重相同
- 页面里同级标题出现 3 层以上
- 要看完一件事需要滚动 3 屏以上
- 每个区块都挂着自己的操作按钮
- 需要用大量分割线、卡片边框来区分信息层次
- 同一屏里同时存在列表、详情、编辑、统计、说明

## 7. 拆分前后对照

### 反例（一页面板式）

需求是「供应商商品维护」，交付成单页：顶部 4 个统计卡 → 筛选条 → 商品表格 → 右侧商品详情 → 详情下方编辑表单 → 底部操作日志 → 页脚帮助说明。滚动 4 屏，主任务不明确。

### 拆法

| 内容 | 落点 |
| --- | --- |
| 统计卡 | 移出到独立看板，或压缩为列表页的一行摘要 |
| 筛选 + 表格 | 一级列表页，唯一主任务是「选出要处理的商品」 |
| 商品详情 | 一级列表页的右侧抽屉，宽度 400px |
| 编辑表单 | 抽屉内的「编辑」进入独立编辑页（字段多） |
| 操作日志 | 详情抽屉内的 Tab |
| 帮助说明 | 帮助中心入口 |
| 高风险操作（下架） | 弹窗确认，写明后果 |

拆完后：列表页只有一个主任务；详情不打断列表；编辑有足够空间；说明不进主任务流。

## 8. 导航层级规则

- 导航最多 3 级：模块 → 列表 → 详情。第 4 级说明对象模型有问题，先重构对象，不要加深导航。
- 每一级都要能回到上一级，且返回后保留筛选、排序、滚动位置。
- 当前所在位置必须可见（高亮导航项或面包屑），不要只靠页面标题。
- 深链可寻址：详情页有自己的 URL，刷新后能回到同一对象。
- 移动端底部 Tab ≤ 5 个，超出的进「更多」。

## 9. 空状态、加载、错误的层级归属

| 情况 | 层级 | 要求 |
| --- | --- | --- |
| 区块内无数据 | 区块内空状态 | 给一个可执行的下一步动作 |
| 整页无数据（首次使用） | 页面级空状态 | 说明这里会出现什么 + 主操作按钮 |
| 区块内加载 | 区块内骨架 | 骨架形状贴近真实内容 |
| 整页加载 | 页面级骨架 | 不要全屏 spinner |
| 字段级错误 | 字段下方 | 错误原因 + 改法 |
| 区块级错误 | 区块内 | 重试按钮 |
| 整页错误（无权限/不存在） | 页面级 | 原因 + 返回或申请权限的下一步 |

原则：报错就地解决，不要让用户为了一个字段错误离开当前层。

## 10. 常见错误

1. 把「管理」当主任务：`商品管理` 不是任务，`审核上架` 才是。
2. 为省一次点击，把详情内联进列表行，结果每行三行文字加两个按钮。
3. Tab 里再放 Tab：说明对象模型没分层，改用详情页 + 分组。
4. 弹窗里嵌表格：弹窗不是容器，改用抽屉或独立页。
5. 用卡片网格承载列表数据：卡片适合展示差异性内容，不适合逐行比较。
6. 统计与操作同屏同权重：看板和操作页分开。
7. 二级页面再给一个全局导航：导航只出现在最外层。
8. 空状态只有一句「暂无数据」：没有下一步，用户只能返回。

- [ ] 能用一句话动词短语说出这个页面的唯一主任务
- [ ] 页面上只有一个主按钮（视觉主导）
- [ ] 一屏内同级区块 ≤ 3
- [ ] 列表、详情、编辑、日志、说明不在同一层
- [ ] 每个 Tab 是同一对象的并列信息组，数量 2–6
- [ ] 高风险动作走弹窗，且写清了后果
- [ ] 返回上一级后筛选与滚动位置保留
- [ ] 空状态、错误态都给了可执行的下一步
