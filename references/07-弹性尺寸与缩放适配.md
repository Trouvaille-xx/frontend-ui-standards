# 弹性尺寸与缩放适配

一条规则：**界面里没有写死的尺寸。** 组件大小由内容与容器决定，由 `rem`、`clamp()`、`min()/max()`、`fr`、容器查询共同控制，不允许用固定 `width` / `height` 把布局钉死。

写死尺寸的界面在 100% 缩放下永远是对的，在 125% 上就开始出问题——而 125% 才是大多数 Windows 用户的默认值。

---

## 1. 为什么必须弹性

同一份代码要在下面五种环境里同时成立：

| 环境 | 用户的实际情况 | 写死尺寸的后果 |
| --- | --- | --- |
| Windows 显示缩放 125%（默认值） | 笔记本高分屏出厂即 125%–150% | 容器变窄后固定宽度溢出，出现横向滚动条 |
| 浏览器页面缩放 150% / 200% | 视力不佳或演示投屏 | 固定高度容器装不下放大的文字，文字被裁 |
| 系统「文本大小」调大 | 无障碍需求 | `px` 字号完全不跟随，`rem` 跟随 |
| 高 DPI 屏（DPR 1.5 / 2） | MacBook、4K 屏 | 1px 边框发虚或消失；位图糊 |
| 窄窗口 / 分屏 / 手机 | 365px 宽的侧边分屏 | 一行按钮挤成一列，弹窗超出屏幕 |

固定尺寸的本质问题是：**它假设了单一渲染环境。** 而这个假设在真实用户那里不成立。

---

## 2. 允许固定 vs 禁止固定

### 允许固定（白名单，这些写死是对的）

| 项 | 值 | 理由 |
| --- | --- | --- |
| 边框、分割线 | `1px` | 物理发丝线，不随内容变化 |
| 圆角 | `4px`–`14px` | 视觉常数 |
| 阴影模糊与偏移 | 固定 | 视觉常数 |
| 动效时长 | `120ms`–`320ms` | 感知常数（`prefers-reduced-motion` 例外） |
| 图标尺寸 | `16` / `20` / `24` | 见 `references/05-图标与SVG规范.md`，本来就规定三档 |
| 触控热区下限 | `min-height: 44px` | 这是**下限**，不是尺寸；用 min 而不是 height |
| 断点 | `@media (min-width: 48em)` | 断点本身用固定值可以，但断点内布局必须流式 |

### 禁止固定（硬伤）

- 容器写死宽度：`width: 1120px`、`max-width: 940px` 配 `margin: 0 auto` 却不处理窄屏
- 组件写死宽高：`width: 320px` 的抽屉、`height: 48px` 的行、`width: 96px` 的操作按钮
- 文本容器写死高度：`height: 40px` 的输入框、`height: 42px` 的列表行
- 字号用 `px`：`font-size: 14px`（不跟随系统文本大小）
- `100vh` / `100vw`：前者在移动端与缩放下溢出，后者含滚动条宽度导致横向滚动
- `zoom` 属性、用 `transform: scale()` 当布局手段
- 用 `overflow: hidden` 掩盖溢出，而不是让它自然换行
- `white-space: nowrap` 配固定宽度（必截断）

## 3. 判定方法：四个测试

任何一个不过，就是写死了。

1. **125% 测试**：Windows 显示缩放切到 125%，页面不出现横向滚动条，内容不被裁。
2. **200% 测试**：浏览器页面缩放 200%（`Ctrl + 加号` 四次），文字放大后容器跟着变高，没有文字被切。
3. **窄屏测试**：窗口拖到 365px 宽，Tab 栏能横向滚动或换行，按钮组换行，弹窗不超出屏幕。
4. **文本注入测试**：把最长的一条文案替换成两倍长度（或塞一个 80 字符的英文单词 / 长 URL），布局不撑破、不重叠。

补充：把系统「文本大小」调到 125%（Settings → 辅助功能 → 文本大小），`rem` 字号应整体变大且布局不坏；若界面毫无变化，说明字号写成了 `px`。

### 怎么测准（别被工具骗了）

- 用 Chrome 无头模式在 Windows 上直接 `--window-size=360,900` 测 360px 会得到错误结论：Chrome 有约 500px 的最小窗口宽度，它按 500 宽布局再把图裁成 360，看起来像溢出，实际没有。
- 精确测法：把一个 360px 宽的 iframe 嵌在探针页里（`<iframe style="width:360px;height:2200px">`），截图就是真实 360 视口。
- 更硬的判据是数字：读 `document.documentElement.scrollWidth` 与 `clientWidth`，`scrollWidth` 必须 ≤ `clientWidth`（允许 1px 误差）。三个宽度都要给数字，不要只看图。

## 4. 弹性手段工具箱

| 场景 | 不要用 | 该用 |
| --- | --- | --- |
| 页面主容器 | `width: 1120px; margin: 0 auto` | `width: 100%; max-width: min(1120px, 100% - 3rem); margin-inline: auto` |
| 两栏 / 三栏 | 固定百分比 + `float` | `display: grid; grid-template-columns: minmax(0, 2fr) minmax(0, 1fr)` |
| 卡片列表 | `width: 320px` | `grid-template-columns: repeat(auto-fit, minmax(min(100%, 16rem), 1fr))` |
| 侧边栏 | `width: 240px` | `width: clamp(13rem, 18vw, 17rem)` 或 `flex: 0 0 auto` + `min-inline-size` |
| 弹窗 | `width: 420px` | `width: 100%; max-width: 26.25rem`（父级 `padding` 兜住窄屏） |
| 抽屉 | `width: 320px` | `width: min(22.5rem, 92vw)` |
| 按钮 | `width: 120px` | `min-height: 2.25rem; padding: 0 1rem` |
| 图标按钮 | `width: 32px; height: 32px` | `min-width: 2.25rem; min-height: 2.25rem; padding: 0` |
| 输入框 | `height: 40px` | `min-height: 2.5rem; padding-block: .5rem`（多行文案自动撑开） |
| 行高 | `height: 42px` | `min-height: 2.625rem` + `align-items: center` |
| 字号 | `font-size: 14px` | `font-size: var(--text-base)`（`.875rem`） |
| 大标题 | `font-size: 32px` | `font-size: clamp(1.5rem, 1.2rem + 1.2vw, 2rem)` |
| 全屏高度 | `height: 100vh` | `min-height: 100dvh`（`dvh` 跟随动态视口） |
| 图片 | `width: 600px` | `width: 100%; height: auto; max-width: 100%` |
| 长文本 | `white-space: nowrap` | `overflow-wrap: anywhere` + 允许换行 |
| 宽表格 | 整页横向滚动 | 表格容器 `overflow-x: auto`，表格 `min-width: 40rem` |

## 5. 关键坑：flex 与 grid 子项被内容撑破

这是最高频的「明明写了 100% 还是溢出」。

```css
/* 错误：长文本把 1fr 撑破，容器溢出 */
.row { display: flex; }
.row__main { flex: 1; }

/* 正确：子项 min-width: 0 才允许收缩 */
.row { display: flex; }
.row__main { flex: 1; min-width: 0; }
```

```css
/* 错误：grid 的 1fr 默认 minmax(auto, 1fr)，auto 下限就是内容宽度 */
.grid { display: grid; grid-template-columns: 1fr 1fr; }

/* 正确：把下限压到 0 */
.grid { display: grid; grid-template-columns: minmax(0, 1fr) minmax(0, 1fr); }
```

记住两句：

- flex 子项默认 `min-width: auto`，会长到内容宽度，必须显式 `min-width: 0`。
- grid 的 `1fr` 等于 `minmax(auto, 1fr)`，要收缩就得写 `minmax(0, 1fr)`。

## 6. 流式字号与间距

固定字号在窄容器里会溢出，在大容器里会显得小。用 `clamp()` 让字号在区间内连续变化：

```css
:root {
  /* 流式字号：最小值、随视口增长、最大值 */
  --fluid-h1: clamp(1.5rem, 1.15rem + 1.4vw, 2rem);
  --fluid-h2: clamp(1.25rem, 1.05rem + .8vw, 1.5rem);
  --fluid-h3: clamp(1.0625rem, .98rem + .4vw, 1.1875rem);
  --fluid-body: clamp(.875rem, .84rem + .16vw, .9375rem);

  /* 流式间距：内容区不再写死 padding */
  --fluid-gutter: clamp(1rem, 3vw, 2rem);
  --fluid-section: clamp(1.5rem, 4vw, 3rem);
}

.page { padding-inline: var(--fluid-gutter); }
.section + .section { margin-top: var(--fluid-section); }
```

约束：

- `clamp()` 的中间值必须带 `vw`，否则不会随容器变。
- 正文最小不低于 `.875rem`（14px），低于这个在 Windows 125% 缩放下会难读。
- 不要对**行高、圆角、边框**做流式，它们会让视觉不稳定。
- `rem` 的根字号不要改（不要把 `html` 设成 `font-size: 62.5%` 之类的技巧），否则会与系统文本大小设置打架。

## 7. 容器查询：组件级自适应

全局断点（`@media`）只回答「屏幕多宽」，组件不知道自己被放进了多宽的容器。同一个卡片放进侧栏和主区，应该长不一样——这只能靠容器查询。

```css
.card-slot { container-type: inline-size; }

.card-list {
  display: grid;
  grid-template-columns: 1fr;
  gap: 12px;
}

/* 容器 ≥ 30rem：两列 */
@container (min-width: 30rem) {
  .card-list { grid-template-columns: repeat(2, minmax(0, 1fr)); }
}

/* 容器 ≥ 45rem：三列 */
@container (min-width: 45rem) {
  .card-list { grid-template-columns: repeat(3, minmax(0, 1fr)); }
}
```

规则：

- 用 `container-type: inline-size` 标记容器，不要在同一个元素上既做容器又依赖自身尺寸。
- 断点用 `rem`，跟随系统文本大小。
- 组件默认（无容器）必须是单列可用状态，容器查询只做增强。
- 兼容兜底：`@supports not (container-type: inline-size)` 时保持单列。

## 8. Windows 缩放专项

### 8.1 1px 边框在 125% / 150% 下发虚

非整数缩放下 1 个 CSS px 落在 1.25 / 1.5 个设备像素上，浏览器要重采样，细线会变灰或消失。

```css
/* 兜底：高 DPI 下用 0.5px 或阴影模拟发丝线，避免重采样 */
@media (min-resolution: 1.5dppx) {
  .hairline { border-width: .5px; }
}
```

不要为了「更清晰」把所有 1px 改成 2px——那在 100% 下会明显变粗。

### 8.2 `100vh` 在缩放后溢出

浏览器缩放 125% 时，视口高度可能不是整数，`height: 100vh` 会多出几个像素，进而产生纵向滚动条；移动端地址栏收起/展开更明显。

```css
/* 用 min-height + dvh，允许内容超出一屏时自然滚动 */
.app { min-height: 100dvh; }
@supports not (height: 100dvh) {
  .app { min-height: 100vh; }
}
```

### 8.3 `100vw` 一定横向溢出

`100vw` 包含滚动条宽度（Windows 上通常 15–17px），用了就必然出现横向滚动条。全宽用 `width: 100%`。

### 8.4 文本放大后按钮被裁

Windows「文本大小」放大后，按钮文字变高，`height: 36px` 的按钮会把文字切掉。改成 `min-height` + `padding`，并允许 `flex-wrap`。

### 8.5 高 DPI 下的位图

`<img>` 必须 `max-width: 100%; height: auto`，并提供 2x 资源或改用 SVG。图标统一用内联 SVG（见 `references/05-图标与SVG规范.md`），天然矢量。

## 9. 常见错误清单

1. `width: 100%` 配 `padding` 但没设 `box-sizing: border-box` → 溢出。全站统一 `*, *::before, *::after { box-sizing: border-box; }`。
2. flex 子项没写 `min-width: 0` → 长文本撑破容器。
3. grid 用 `1fr` 而不是 `minmax(0, 1fr)` → 同理。
4. 弹窗写 `width: 420px` → 365px 宽的分屏下直接超出屏幕。
5. 表格 `table-layout: fixed` + 固定列宽 → 长内容截断；改 `table-layout: auto` + `overflow-x: auto` 容器。
6. 绝对定位元素写 `left: 300px` → 容器变窄后跑到屏幕外；改用 `inset-inline-end` + 百分比或 `flex` 布局。
7. 用 `!important` 顶掉响应式规则。
8. 图片不给 `max-width: 100%` → 撑破卡片。
9. 用 `aspect-ratio` 需要高度自适应时写成固定 `height`。
10. 卡片间距用 `margin` 而不是 `gap` → 换行后行间距错乱。
11. 横向滚动的 Tab 栏用 `overflow: hidden` 而不是 `overflow-x: auto`。
12. 只在 1920 宽屏上验收，从不在 125% 缩放下看。

## 10. 反例对照

| 现象 | 违规 | 改法 |
| --- | --- | --- |
| 125% 缩放下出现横向滚动条 | 固定 `width: 1120px` | `max-width: min(1120px, 100% - 3rem)` |
| 200% 缩放后按钮文字被裁 | `height: 36px` | `min-height: 2.25rem; padding: 0 1rem` |
| 系统文本放大后界面不变 | `font-size: 14px` | `font-size: var(--text-base)`（`.875rem`） |
| 移动端底部被地址栏遮住 | `height: 100vh` | `min-height: 100dvh` |
| 侧栏里的卡片挤成一条 | 只用全局 `@media` 断点 | `@container` 容器查询 |
| 弹窗在 365px 宽屏超出 | `width: 420px` | `width: 100%; max-width: 26.25rem` |
| 长英文 URL 撑破卡片 | 无 `overflow-wrap` | `overflow-wrap: anywhere` |
| 表格把整页撑出横向滚动 | 表格直接放页面 | 容器 `overflow-x: auto` |

## 11. 验收清单

- [ ] 页面容器有 `max-width` 上限且窄屏不贴边（`min(上限, 100% - 边距)`）
- [ ] 全站无 `width` / `height` 固定像素值（白名单除外）
- [ ] 字号全部 `rem` 或 `clamp()`，根字号未被改写
- [ ] 无 `100vh` / `100vw` / `zoom` / 布局用 `transform: scale()`
- [ ] flex 子项有 `min-width: 0`，grid 列用 `minmax(0, 1fr)`
- [ ] 文本容器无固定高度，长文本有 `overflow-wrap: anywhere`
- [ ] 图片有 `max-width: 100%; height: auto`
- [ ] 宽表格/代码块有 `overflow-x: auto` 容器，页面本身不横向滚动
- [ ] 组件用 `@container` 自适应容器宽度，不依赖全局断点
- [ ] 125% / 150% / 200% 缩放与 365px 窄屏四测全过

自动化脚本（`width` / `height` / `font-size` 固定值必须为 0）：

```powershell
$h = [IO.File]::ReadAllText((Resolve-Path .\index.html), [Text.Encoding]::UTF8)

# 固定宽高：应为 0（min-/max- 前缀不计入）
[regex]::Matches($h, '(?<![a-z-])(?:width|height)\s*:\s*[0-9]{2,}px').Count

# 固定字号：应为 0
[regex]::Matches($h, 'font-size\s*:\s*[0-9]+px').Count

# 视口单位与 zoom：应为 0
[regex]::Matches($h, '100vh|100vw|(?<![a-z-])zoom\s*:').Count

# 全站 box-sizing 兜底：应为 1
[regex]::Matches($h, '\*[^{]*\{[^}]*box-sizing\s*:\s*border-box').Count
```

命中不为 0 时，逐条对照第 4 节工具箱替换；`min-height` / `min-width` / `max-width` 的白名单值不需要改。

## 12. 与其它规范的关系

- 与禁令 4（禁一页面板式）同源：写死尺寸的核心动机往往是「一屏塞下所有信息」，弹性布局会逼你把信息分层。
- 与 `references/03-交互与反馈.md` 第 10 节（触屏热区 44px 下限、`env(safe-area-inset-*)`）配合使用。
- 与 `references/05-图标与SVG规范.md` 的 16/20/24 三档尺寸是同一套栅格。
- 动效降级：`prefers-reduced-motion` 与容器查询、`resize` 交互要同时生效，别只降级动画。
